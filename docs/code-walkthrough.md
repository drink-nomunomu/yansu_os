# YansuOS ソースコード解説

このドキュメントでは、`repo/yansu/src/` 以下の各ソースファイルの役割と実装について解説します。

## ファイル構成概要

```
src/
├── main.rs          # エントリーポイント（ブートローダーのメイン処理）
├── lib.rs           # ライブラリクレートのルート
├── allocator.rs     # メモリアロケータの実装
├── graphics.rs      # グラフィック描画システム
├── init.rs          # システム初期化
├── print.rs         # 出力・ログ機能
├── qemu.rs          # QEMU特有の機能
├── result.rs        # エラーハンドリング
├── serial.rs        # シリアル通信
├── uefi.rs          # UEFI API ラッパー
├── x86.rs           # x86アーキテクチャ固有機能
└── test_runner.rs   # テストフレームワーク
```

## 各ファイルの詳細解説

### 1. main.rs - エントリーポイント

**役割**: UEFIブートローダーのメイン処理

**主要機能**:
- `efi_main`関数: UEFI環境からの最初のエントリーポイント
- システム初期化と基本的な動作テスト
- グラフィック出力とメモリ情報の表示

**処理フロー**:
1. ブート開始メッセージの出力
2. VRAM（ビデオメモリ）の初期化
3. 画面のクリアとテストパターン描画
4. メモリマップの取得と解析
5. システム情報（CR3レジスタ等）の表示
6. 無限ループでシステム待機

**重要なコード**:
```rust
#[no_mangle]
fn efi_main(image_handle: EfiHandle, efi_system_table: &EfiSystemTable) {
    // システム初期化とメイン処理
}
```

### 2. lib.rs - ライブラリルート

**役割**: クレート全体の構成管理

**主要機能**:
- 各モジュールの公開設定
- テスト環境の設定（`#![test_runner]`）
- `no_std`環境での特殊機能有効化

### 3. print.rs - 出力・ログシステム

**役割**: デバッグ出力とログ機能の提供

**主要機能**:
- **マクロ定義**: `print!`, `println!`, `info!`, `warn!`, `error!`
- **hexdump機能**: メモリ内容の16進ダンプ表示
- **シリアル出力**: `SerialPort`経由でのテキスト出力

**実装の特徴**:
- 構造化ログでファイル名・行番号を自動追加
- ASCII文字とバイナリデータの両方表示に対応したhexdump
- `fmt::Write` traitを活用した汎用的な出力システム

**使用例**:
```rust
println!("Booting YansuOS...");
info!("システム初期化完了");
hexdump(&memory_descriptor);
```

### 4. serial.rs - シリアル通信

**役割**: RS-232Cシリアルポート経由の通信

**主要機能**:
- **COM1ポート制御**: I/Oポート0x3f8を使用
- **初期化処理**: ボーレート115200bps、8N1設定
- **文字送信**: 個別文字・文字列の送信機能

**技術詳細**:
- UARTレジスタへの直接アクセス
- 送信バッファの状態監視
- `fmt::Write` trait実装による標準出力統合

**レジスタ操作**:
```rust
// DLAB設定（ボーレート設定モード）
write_io_port_u8(self.base + 3, 0x80);
// ボーレート設定（115200bps）
write_io_port_u8(self.base, 0x01);
```

### 5. x86.rs - x86アーキテクチャ固有機能

**役割**: x86_64 CPUの低レベル制御

**主要機能**:
- **HLT命令**: CPU待機状態への移行
- **I/Oポートアクセス**: ハードウェアレジスタ読み書き
- **システムレジスタアクセス**: CR3（ページテーブルベース）読み取り
- **CPU最適化**: PAUSEによるビジーループヒント

**アセンブリ統合**:
```rust
pub fn hlt() {
    unsafe { asm!("hlt") }
}

pub fn read_cr3() -> *mut RootPageTable {
    let mut cr3: *mut RootPageTable;
    unsafe {
        asm!("mov rax, cr3", out("rax") cr3)
    }
    cr3
}
```

### 6. qemu.rs - QEMU統合機能

**役割**: QEMU仮想マシンとの連携

**主要機能**:
- **デバッグ終了**: QEMUプロセスの制御された終了
- **終了コード**: 成功/失敗ステータスの設定

**実装**:
- I/Oポート0xf4を使用したQEMU debugexit デバイス制御
- 終了コードに応じたQEMUプロセスの戻り値制御

### 7. init.rs - システム初期化

**役割**: 基本ランタイム環境の構築

**主要機能**:
- **UEFI Boot Services終了**: EFI環境からの離脱
- **メモリマップ取得**: 利用可能メモリ領域の把握
- **アロケータ初期化**: メモリ管理システムの準備

**初期化シーケンス**:
1. メモリマップの取得
2. UEFI Boot Servicesからの離脱
3. カスタムアロケータの初期化

### 8. graphics.rs - グラフィックシステム

**役割**: 画面描画とビットマップ操作

**主要機能**:
- **Bitmap trait**: 汎用ビットマップインターフェース
- **描画プリミティブ**: ピクセル描画、矩形塗りつぶし
- **安全性チェック**: 座標範囲の検証
- **フォントレンダリング**: テキスト描画機能

**設計思想**:
- trait based な抽象化で異なるフレームバッファ形式に対応
- unsafe操作の最小化と境界チェック
- 効率的な描画アルゴリズム

### 9. uefi.rs - UEFI APIラッパー

**役割**: UEFI仕様の低レベルAPIを安全にカプセル化

**主要機能**:
- **システムテーブル操作**: EFI System Tableアクセス
- **グラフィックプロトコル**: Graphics Output Protocol使用
- **メモリ管理**: メモリマップとメモリタイプ管理
- **VRAMアクセス**: フレームバッファへの直接書き込み

**重要な構造体**:
- `EfiSystemTable`: UEFI環境の中核情報
- `EfiGraphicsOutputProtocol`: 画面制御インターフェース
- `EfiMemoryDescriptor`: メモリ領域の詳細情報
- `VramTextWriter`: VRAM直接テキスト描画

### 10. allocator.rs - メモリアロケータ

**役割**: カスタムメモリ管理システム

**主要機能**:
- **ヒープ管理**: 動的メモリ割り当て
- **フリーリスト**: 利用可能メモリ領域の管理
- **アライメント**: メモリ境界の調整
- **GlobalAlloc trait**: Rustの標準アロケータインターフェース実装

**アルゴリズム**:
- リンクリスト形式のフリーブロック管理
- First-fit アロケーション戦略
- ヘッダー付きチャンク管理

### 11. result.rs - エラーハンドリング

**役割**: エラー処理の統一化

**実装**:
```rust
pub type Result<T> = core::result::Result<T, &'static str>;
```

シンプルな文字列ベースのエラー型を定義し、プロジェクト全体で一貫したエラーハンドリングを提供。

### 12. test_runner.rs - テストフレームワーク

**役割**: 自動テスト実行環境

**主要機能**:
- **Testable trait**: テスト可能な関数の抽象化
- **テストランナー**: 複数テストの順次実行
- **結果レポート**: 成功・失敗の統計表示
- **QEMU統合**: テスト結果に基づく自動終了

**実行フロー**:
1. 全テストの列挙と実行
2. 各テストの開始・終了ログ出力
3. 全体結果の集計
4. QEMU終了コードの設定

## モジュール間の関係

### 依存関係
- `main.rs` → すべてのモジュールを使用
- `print.rs` → `serial.rs`に依存
- `serial.rs` → `x86.rs`のI/O機能を使用
- `init.rs` → `uefi.rs`と`allocator.rs`を統合
- `graphics.rs` → `uefi.rs`のVRAM機能を使用

### データフロー
1. **起動**: `main.rs` → `init.rs` → `uefi.rs`
2. **描画**: `main.rs` → `graphics.rs` → `uefi.rs`
3. **ログ**: `print.rs` → `serial.rs` → `x86.rs`
4. **メモリ**: `allocator.rs` ← `uefi.rs`

## 設計パターン

### 1. Trait による抽象化
- `Bitmap` trait: 異なる画面形式への対応
- `Testable` trait: 汎用テスト機能

### 2. unsafe の分離
- 低レベル操作を特定モジュール(`x86.rs`, `uefi.rs`)に集約
- 上位層では安全なAPIのみ使用

### 3. マクロによる利便性
- ログ出力マクロで開発効率向上
- テスト用マクロで品質保証

この構成により、YansuOSは安全性と性能を両立したモジュラーな設計を実現しています。
